# 字幕源搜索策略

拾幕先从任务路径和 Jellyfin 缓存整理出统一的媒体信息，再交给各字幕源适配器。
可用信息包括中文标题、原始标题、年份、IMDb/TMDb ID、文件名、季号和集号。
不同站点能力不同，因此各适配器采用自己的回退顺序，而不是强行共用一条查询。

## 电影

### Zimuku

1. 中文标题 + 年份
2. 原始标题 + 年份
3. 中文标题
4. 原始标题

站点没有公开的 IMDb/TMDb 查询接口。每次检索仍会用年份和标题检查作品页；标题
明确匹配时允许站点年份与媒体库年份相差 1 年，以兼容影展、院线和流媒体发行年份
不同的情况，差距更大的结果仍会拒绝。找到有效候选后停止后续回退。

### ASSRT

1. 中文标题 + 年份
2. 原始标题 + 年份
3. 中文标题
4. 原始标题

ASSRT API 以文本检索为主。下载前还会从详情文件名提取年份，拒绝明确冲突的电影。

### SubDL

1. IMDb ID
2. 原始标题
3. 中文标题
4. 视频文件名

使用 SubDL v2 API。先确定站内作品 ID，再按作品 ID 获取中文字幕；IMDb 完全匹配的
结果优先。API Key 只用于检索，免费账户默认使用站点允许的匿名下载链接。

### Subliminal

拾幕把标题、原始标题、年份、IMDb ID 和文件信息交给 Subliminal。OpenSubtitles.com
优先使用原始标题，其他内置来源使用媒体标题，具体请求和匹配由 Subliminal 管理。
拾幕不修改 Subliminal 的内部实现。

## 剧集

- Zimuku、ASSRT：先搜索“剧名 + Sxx”整季包，无结果后搜索 `SxxExx` 单集。
- SubDL：依次用 IMDb ID、原始剧名、中文剧名和文件名定位剧集，再把季号、集号
  作为 API 条件查询。
- Subliminal：传入剧名、年份、IMDb ID、季号、集号和文件名，由其内部来源匹配。

整季包成功下载后会缓存同季字幕，后续单集优先匹配缓存，不重复调用字幕站。

## 通用规则

- 字幕源按用户配置的优先级依次搜索，找到可用候选后不再调用后续来源。
- 每个来源独立限速；本地字幕检查和整季包缓存匹配不受网络搜索间隔限制。
- 结构、语言、年份、季集和重试黑名单会在候选下载前后分层校验。
- 搜索日志记录实际查询值、查询来源、策略、媒体 ID 和返回数量，便于复查漏搜。
