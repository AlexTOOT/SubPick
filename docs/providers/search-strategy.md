# 字幕源搜索策略

拾幕先从媒体目录中的 NFO 整理出统一且冻结的媒体身份，再交给各字幕源适配器。
电影使用 `movie.nfo`（缺失时才回退同名 NFO），剧集使用 `tvshow.nfo` 并结合有效的
分集 NFO 或文件名 `SxxExx`。可用信息包括中文标题、原始标题、年份、IMDb/TMDb ID、
文件名、季号和集号；Jellyfin 缓存不参与身份或年份补全。
不同站点能力不同，因此各适配器采用自己的回退顺序，而不是强行共用一条查询。

## 电影

### Zimuku

1. 中文标题 + 年份
2. 原始标题 + 年份
3. 中文标题
4. 原始标题

站点没有公开的 IMDb/TMDb 查询接口。每次检索仍会用年份和标题检查作品页；标题
明确匹配时允许站点年份与媒体库年份相差 1 年，以兼容影展、院线和流媒体发行年份
不同的情况，差距更大的结果仍会拒绝。剧集作品页执行相同的稳定年份检查。中文
作品名会先去除季、集和地区版标签后再比较，避免把“办公室”误命中“传奇办公室”。
找到有效候选后停止后续回退。

作品身份和语言条件相同时，候选优先参考下载量，再参考字幕库评分。这些站内数据会
归一化为 Adapter 原生质量分，只在 Zimuku 候选内部比较。

### ASSRT

1. 中文标题 + 年份
2. 原始标题 + 年份
3. 中文标题
4. 原始标题

ASSRT API 以文本检索为主。下载前还会从详情文件名提取年份，拒绝明确冲突的电影。
搜索结果中的 `langdou=true` 按中文双语处理，下载后仍由通用语言检查确认实际内容。

为避免少量投票造成排序失真，拾幕会读取每个候选的详情数据：下载量占主要权重，
`vote_score` 占次要权重，浏览量仅用于日志展示。详情结果会短时缓存在内存中，随后
下载同一候选时不会重复查询。ASSRT 实际配额通常只有每分钟 5 次，因此候选较多时
搜索会明显变慢；这是启用 ASSRT 后为提高字幕质量付出的等待时间。

### SubDL

1. IMDb ID
2. TMDb ID
3. 原始标题
4. 中文标题
5. 视频文件名

使用 SubDL v2 API。先确定站内作品 ID，再按作品 ID 获取中文字幕；IMDb 完全匹配的
结果优先，其次是 TMDb 完全匹配；没有外部 ID 命中时按作品年份和标题选择，明确
属于远隔年份同名作品的结果会放弃并继续下一种查询。API Key 只用于检索，免费账户
默认使用站点允许的匿名下载链接。剧集候选同时核对季号和集号。

### Subliminal

拾幕把标题、原始标题、年份、IMDb ID 和文件信息交给 Subliminal。OpenSubtitles.com
优先使用原始标题，具体请求和匹配由 Subliminal 管理。已经停止向普通用户提供服务的
OpenSubtitles.org XML-RPC 来源不再启用。拾幕不修改 Subliminal 的内部实现。

## 剧集

- Zimuku：整季包优先。依次尝试中文“剧名 + 第二季”、英文“剧名 + Season 2”和
  `剧名 + S02`；整季无结果时，再依次尝试中文“剧名 + 第二季第三集”、英文
  “剧名 + Season 2 + Episode 3”和 `剧名 + S02E03`。中文标题始终排在原始标题前。
- ASSRT：先搜索“剧名 + Sxx”整季包，无结果后搜索 `SxxExx` 单集。
- SubDL：依次用 IMDb ID、原始剧名、中文剧名和文件名定位剧集，再把季号、集号
  作为 API 条件查询。
- Subliminal：传入剧名、年份、IMDb ID、季号、集号和文件名，由其内部来源匹配。

整季包成功下载后会缓存同季字幕，后续单集优先匹配缓存，不重复调用字幕站。
剧集任务同时保留父级剧集首播年和当季/单集首播年；候选年份与任一已知年份匹配均可
通过，避免同一季在不同字幕站被标记为不同发行年份时误删正确结果。

## 中文与双语识别

- Zimuku 根据搜索结果的语言图标与文字识别简体、繁体和双语，下载后再解析字幕文本。
- ASSRT 接受明确中文标记，也把站点的 `langdou=true` 视为包含中文的双语候选；
  下载后的内容检查仍是最终防线。
- SubDL 接受官方中文语言代码，包括简体、繁体和中英双语代码。
- Subliminal 使用其公开语言对象返回候选，拾幕不修改依赖包内部的语言解析。

以上规则只决定候选是否进入后续流程。下载后仍会检查字幕结构、中文内容和字幕时间
轴；已知视频时长时，明显超出视频或只覆盖长片前半段的字幕不会直接落库。

## 通用规则

- 字幕源按用户配置的优先级依次搜索，找到可用候选后不再调用后续来源。
- 不跨字幕源比较候选分数。所有候选排序仅发生在当前 Adapter 的搜索结果内部。
- 先过滤明确错误的作品、年份和季集，再按 Adapter 提供的 `provider_quality` 排序。
- 对剧集候选，匹配整季包获得 42 分季集适配加分，精确匹配单集获得 40 分；
  同等站内质量下优先整季包，以便缓存并复用于同季后续任务。
  站点下载量、评分等原始数据保留在候选元数据与任务日志中。
- 双语是条件偏好：只有原生质量接近当前最佳候选时才获得加分，避免低下载量双语
  字幕压过明显更可靠的高下载量简体或繁体字幕。
- 用户重试时会排除已使用过的稳定候选 ID 或详情页地址；当前来源没有其他可用候选
  时，流程继续尝试下一个来源。
- 每个来源独立限速；本地字幕检查和整季包缓存匹配不受网络搜索间隔限制。
- 稳定作品标题、稳定作品年份、结构、语言、季集、时间轴和重试黑名单会在候选
  下载前后分层校验；发布文件名不作为稳定作品标题使用。
- 搜索日志记录实际查询值、查询来源、策略、媒体 ID 和返回数量，便于复查漏搜。
